Bank Account Management System

A Java project demonstrating inheritance, method overriding, abstract classes, interfaces, collections, exception handling and Swing.

Summary

Problem: different account types follow different rules, so treating every account the same breaks down. Savings accounts need a minimum balance and earn interest, while current accounts allow an overdraft and earn none.

Method: the system uses an interface (Transactable), an abstract class (Account) and two subclasses that override withdrawal and interest rules. A Bank class stores accounts in a LinkedHashMap, custom exceptions handle errors, and a Swing GUI provides the interface.

Outcome: headless testing confirmed correct deposits, withdrawals, transfers, interest and history, with invalid operations rejected by clear messages.

Background

Banking is a classic domain for teaching object-oriented programming because accounts share structure but differ in rules. Abstraction captures the common parts, inheritance reuses them, polymorphism lets each type apply its own behaviour, and encapsulation protects the balance.

Banking software must also fail safely. Overdrawing, entering negative amounts or searching for a missing account should never crash the program, so Java exception handling reports each case clearly.

Objectives

  1. Model account types with an abstract class and inheritance.
  2. Define the transaction contract with an interface.
  3. Apply method overriding for type-specific withdrawal and interest rules.
  4. Store accounts and history in Java Collections.
  5. Handle errors with custom exceptions and try/catch.
  6. Provide a Swing GUI for all operations.
  7. Test both valid and invalid operations.
